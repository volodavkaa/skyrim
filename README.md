# Skyrim Mod Packer

Десктопна програма для Windows x64: пакування модів у ZIP, перевірка ESL та створення плагінів одноручних мечів для Skyrim SE/AE.

Стек: C# 12, .NET 8, WPF, WPF-UI 3, CommunityToolkit.Mvvm, Microsoft.Extensions.Hosting/DI, Serilog. Робота з плагінами — Mutagen.Bethesda.Skyrim 0.53.1. Нові модулі використовують формат Skyrim SE; сумісність редактора з Skyrim VR не перевірялася.

## Пакування

1. У **Налаштуваннях** вкажіть папку `Data` гри або натисніть автоматичний пошук. Вкажіть вихідну папку поза грою (типово — робочий стіл), збережіть налаштування. Доступні українська й англійська мови, світла й темна теми.
2. Для старого сценарію у **Профілях** задайте назву, версію, ключові слова й плагін. Для робочого моду створіть або прив’яжіть профіль на вкладці «Зброя»: він також отримає шлях до `mod-project.json`.
3. У **Збірці** виберіть профіль → **Сканувати** → перевірте знайдені файли → запустіть пакування.
4. ZIP містить плагін у корені та відносні шляхи ресурсів (`meshes/`, `textures/`, `sound/`, `SKSE/`). Результат і помилки відображаються у журналі.

Профілі без `WeaponProjectPath` використовують старий сканер Data за входженням ключових слів у шляхи. Зовнішній плагін пакується з указаного шляху; якщо файл відсутній, збірка завершується помилкою. Профілі з `WeaponProjectPath` пакують плагін і явно зареєстровані ресурси проєкту, без пошуку за ключовими словами. Однакові шляхи у Data не підміняють файли проєкту.

**Відоме обмеження наявного сценарію:** дерево дозволяє змінювати вибір файлів, але команда пакування повторно сканує джерело й не передає ці виключення в конвеєр. Перевіряйте вміст ZIP. Для старих профілів відбір задають ключові слова; проєктні профілі включають усі зареєстровані ресурси. Це місце не рефакторилось у межах додавання модулів.

## ESL

- **Аналіз ESL** на екрані збірки читає плагін і показує версію заголовка, кількість власних і проблемних записів та причини несумісності. Перевизначення записів майстрів не рахуються як власні.
- Перевіряється ліміт 4096 власних записів і діапазон локальних FormID: `0x800–0xFFF` для заголовка до 1.71, `0x001–0xFFF` для 1.71 і новіших. Нульовий ID недопустимий. Через розмір діапазонів фактична місткість становить 2048 і 4095 різних ID відповідно.
- Увімкніть ESL у профілі, щоб додати прапорець **Small master (ESL)** під час пакування. Типово опцію вимкнено, зокрема для старих профілів.
- Крок працює зі staging-копією навіть за вимкненого звичайного тимчасового копіювання. Несумісність перериває збірку; початковий плагін залишається незмінним. Уже встановлений прапорець повторного запису не потребує.
- Перед зміною зберігається резервна копія: `<шлях-архіву>.backups/<ідентифікатор-збірки>/<плагін>.bak`. Вона залишається поза ZIP. Результати записуються в журнал.

Компактування FormID не реалізовано: етап 7 пропущено. Увімкнення ESL не перенумеровує записи.

## Редактор «Зброя»

1. Налаштуйте шлях до `Data` з `Skyrim.esm`. На вкладці **Зброя** натисніть **«Створити мод зброї»**, задайте ім’я, `.esp` або `.esl` і робочу папку поза грою. Типова папка: `%LocalAppData%\SkyrimModPacker\Plugins`. У ній створиться окрема підпапка з ім’ям плагіна: сам плагін, `mod-project.json`, порожні `meshes` і `textures`. Skyrim.esm додається до майстрів автоматично; додаткові майстри вводяться через кому в порядку залежностей.
2. Кнопкою **«Далі»** перейдіть у **«Шаблон»**. Skyrim.esm завантажується автоматично. Знайдіть одноручний меч за назвою або EditorID; для нового предмета виберіть шаблон або натисніть **«Новий меч із вибраного шаблону»**. Для редагування виберіть наявний меч у списку. Видалення блокується, якщо на нього посилаються записи плагіна.
3. На кроці **«Модель»** додайте власну NIF і DDS або залиште модель шаблону. Шлях задається відносно `meshes`, без абсолютного шляху або `..`; імпорт заповнює його автоматично.
4. На кроці **«Властивості»** задайте назву, урон, вагу й вартість. EditorID пропонується автоматично з уникненням збігів серед мечів і доступний для зміни. Опис, швидкість, досяг, ключові слова, звук, чари й заряд містяться у **«Додаткових властивостях»**. Решта успадковується від шаблону. Помилки показуються поруч із полями й блокують перехід.
5. На **«Підсумку»** перевірте джерело, модель, характеристики й список файлів. Зміни показано стрілкою та виділено. Натисніть **«Зберегти меч у плагін»**: для нового предмета створиться власний запис із новим FormID, для наявного — оновиться вибраний запис. Самі переходи «Назад / Далі» не записують меч і не скидають введені дані. Кнопки навігації закріплені внизу вікна.
6. Необов’язковий розділ **«Отримання в грі»** на підсумку містить рецепти COBJ та leveled lists. Спершу збережіть меч; рецепти й списки записуються окремими кнопками. Рецепт задає верстат, матеріали, кількість результату й необов’язковий перк. LVLI створює override ванільного списку зі збереженням початкових записів; це не злиття всіх активних модів, тому враховуйте порядок завантаження.
7. На підсумку натисніть **«Запакувати робочий мод»**. За потреби ввімкніть ESL. Без вибраного профілю створиться новий; вибраний профіль має бути прив’язаний до поточного плагіна. Папка виводу береться з налаштувань (типово — робочий стіл), шлях готового ZIP з’явиться на екрані. Збережений проєктний профіль також працює через **«Збірка → Сканувати → Запакувати»**.

Редактор зараз працює лише з одноручними мечами. Списки ванільних шаблонів і варіантів посилань читаються зі `Skyrim.esm`. Нові власні записи отримують послідовні ID `0x800–0xFFF`, заголовок 1.70; після видалення ID не перевикористовуються. За вичерпання діапазону запис відхиляється.

Екран адаптується до ширини: секції стають у дві колонки на широкому вікні та послідовно на вузькому. Регулятор **«Масштаб»** унизу змінює розмір вмісту від 85% до 130% у поточному вікні; кнопки навігації залишаються доступними. Бічна навігація головного вікна переходить до компактних іконок при звуженні. Оформлення використовує наявні ресурси теми WPF-UI.

### Продовження роботи та копія плагіна

- **«Відкрити робочий мод»** на кроці «Мод» відкриває `mod-project.json`. Проєкт зберігається автоматично при створенні, зміни мечів — дією збереження на підсумку. Незбережені поля редактора залишаються лише в поточному вікні. Папку проєкту можна перенести цілком: шлях плагіна в JSON відносний, шлях до Data береться з налаштувань цього комп’ютера.
- **«Створити робочу копію»** дозволяє вибрати ESP/ESL, зокрема з папки гри. У вибраній робочій папці створюється новий проєкт із копією плагіна без зміни його імені та FormID. Наявний проєкт не перезаписується. Підтримуються нелокалізовані плагіни з власними одноручними мечами; ESM і плагіни лише з overrides цим способом не імпортуються.
- Створення робочої копії переносить лише плагін. Моделі й текстури додаються окремо, як описано нижче; ванільні посилання продовжують використовувати ресурси гри.
- **«Відкрити робочий плагін»** залишено для окремих ESP/ESL поза грою без файлу проєкту. Після успішного відкриття такого файлу поточний проєкт від’єднується. Skyrim.esm через цю кнопку відкривати не потрібно.

Перед перезаписом плагіна редактор зберігає попередню версію поруч як `<плагін>.bak`; ця копія оновлюється при наступному успішному записі. Для довшої історії зберігайте окремі копії. Запис виконується через тимчасовий файл. Файли в папці гри редактор і ESL-сервіс лише читають; запис усередину гри та через символічні посилання/ junction заборонений.

### Власна NIF-модель і текстури

1. Створіть або відкрийте робочий мод і виберіть меч чи ванільний шаблон. На кроці **«Модель»** натисніть **«Додати свою NIF-модель»** або перетягніть один `.nif` у зону імпорту.
2. Якщо джерело лежить під `meshes`, його відносний шлях зберігається. В інших випадках модель копіюється в `meshes/<назва-проєкту>/<ім’я>.nif`. Шлях у редакторі заповнюється автоматично. Запишіть його в плагін кнопкою **«Зберегти меч у плагін»** на підсумку.
3. Розкрийте **«Модель і текстури проєкту»**. Додайте готові `.dds` файлами або папкою. Шляхи під `textures` зберігаються: вибір `textures/Custom` залишає `textures/Custom/...`. Для папки поза `textures` зберігається її ім’я; для окремих файлів можна задати підпапку, наприклад `Custom/Metal`. Якщо вказано підпапку для зовнішньої папки, вона додається перед її ім’ям.
4. Звірте список відносних шляхів із шляхами, які використовує NIF. Імпорт не змінює посилання всередині моделі й не знаходить текстури автоматично. Підтримуються лише непорожні NIF/DDS; інші файли в папці текстур пропускаються.
5. **«Перевірити модель і додані файли»** перевіряє наявність і ненульовий розмір файлів проєкту. Вміст NIF/DDS, відповідність текстур і вигляд у грі не перевіряються. Для успадкованої ванільної моделі, яка міститься в BSA, ця перевірка не підтверджує її наявність у проєкті.

Список ресурсів зберігається в `mod-project.json` відносними шляхами. Перед його оновленням створюється `.bak`. Наявні ресурси не перезаписуються; файл, який уже лежить за своїм цільовим шляхом у проєкті, можна зареєструвати без копіювання. При помилці копіювання чи запису метаданих нові файли операції видаляються. Якщо зареєстрована модель зникла, збереження меча з цим посиланням блокується.

### Пакування робочого проєкту

- ZIP містить плагін у корені й усі зареєстровані NIF/DDS у `meshes/` та `textures/`. JSON проєкту, `.bak`, тимчасові й незареєстровані файли не включаються. Ванільні моделі, успадковані від шаблонів Skyrim.esm, не потрібно копіювати з гри.
- До пакування перевіряються збережений плагін, зареєстровані файли та шляхи моделей власних мечів. Відсутній або порожній ресурс, незареєстрована власна модель чи невідповідність плагіна профілю зупиняє збірку. Після попереднього перегляду джерело перевіряється повторно; підміни відсутніх файлів версіями з Data немає.
- Пакування з майстра вимагає попереднього збереження меча; незбережені зміни основних і додаткових полів блокують дію. Із вкладки «Збірка» пакується стан, уже записаний у файли.
- ESL встановлюється лише на staging-копії спільним конвеєром. Початковий плагін та ресурси проєкту залишаються незмінними, резервні копії ESL зберігаються поруч із ZIP у `.backups`.
- Для проєктних архівів папка виводу має бути поза грою. Наявний архів не перезаписується без відповідного налаштування; змінити версію можна у профілі.
- Старі профілі, створені до появи прив’язки проєкту, зберігають попередню поведінку. Відкрийте проєкт і натисніть «Прив’язати до вибраного профілю», щоб включити його ресурси. Після перенесення папки проєкту профіль теж потрібно прив’язати заново.

Перевірка наявності файлів не аналізує внутрішні посилання NIF на текстури та не підтверджує вигляд моделі в грі.

## Дані та журнал

У `%LocalAppData%\SkyrimModPacker` зберігаються `settings.json`, `profiles.json`, `build_history.json`, а в підпапці `logs` — щоденні файли журналу `log-*.txt` (до 7 файлів). У вікні журналу зберігаються останні 1000 подій. Профілі містять версію, ключові слова, ім’я та необов’язкові зовнішні шляхи плагіна й проєкту, опцію ESL. Вихідна папка є загальним налаштуванням.

Автоматичне підвищення версії та обчислення SHA-256 архіву в поточному сценарії не реалізовані. JSON-збереження не має транзакційної синхронізації; очищення загального staging при скасуванні між кроками залишається обмеженням наявного конвеєра.

## Архітектура

| Проєкт | Призначення |
|---|---|
| `src/SkyrimModPacker.Core` | Моделі, `Result`, інтерфейси `IPackStep`, `IEslService`, `IPluginBuilderService`, захист шляхів запису |
| `src/SkyrimModPacker.Application` | `Services/PackingPipeline`, кроки в `Steps`, їх реєстрація в DI |
| `src/SkyrimModPacker.Infrastructure` | `FileSystem/ProfileModScanner` обирає проєктне джерело або старий `ModScanner`; `SkyrimLocator`, `ZipArchiver`, JSON-репозиторії, `Esl`, `PluginBuilder`, логування |
| `src/SkyrimModPacker.UI` | WPF MVVM, навігація, `ViewModels`, `Views/Pages`, ресурси української й англійської мов; DI у `App.xaml.cs` |
| `tests/SkyrimModPacker.Tests` | xUnit, NSubstitute, синтетичні плагіни, інтеграційні сценарії та WPF-перевірки |

Кроки виконуються за `Order`: **Scan (100) → Filter (200) → Validate (300) → Copy (400) → ESL (450, необов’язковий) → Archive (500)**. Нові кроки реалізують `IPackStep` і реєструються в `Application/DependencyInjection.cs`; нові сервіси — в `Infrastructure/DependencyInjection.cs`.

Приклад додаткового кроку:

```csharp
using SkyrimModPacker.Core.Interfaces;
using SkyrimModPacker.Core.Models;

public sealed class CustomStep : IPackStep
{
    public string Name => "Custom step";
    public int Order => 475;

    public Task<bool> ExecuteAsync(PackingContext context,
        CancellationToken cancellationToken = default)
    {
        cancellationToken.ThrowIfCancellationRequested();
        // При помилці додайте пояснення в context.Errors і поверніть false.
        return Task.FromResult(true);
    }
}
```

Реєстрація: `services.AddSingleton<IPackStep, CustomStep>();`. Наявний ZIP-архіватор використовує `System.IO.Compression`; контракт `IArchiver.CreateArchiveAsync` приймає вихідний шлях і список пар `(SourcePath, EntryPath)`.

## Збірка і тести

Потрібні Windows 10/11 x64, .NET 8 SDK або сумісний новіший SDK та доступ до NuGet для першого відновлення. WPF-тести виконуються на Windows.

З кореня репозиторію:

```powershell
dotnet restore SkyrimModPacker.sln
dotnet test SkyrimModPacker.sln -c Release --no-restore --verbosity minimal
dotnet publish src/SkyrimModPacker.UI/SkyrimModPacker.UI.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish/win-x64
```

Запуск: `publish/win-x64/SkyrimModPacker.UI.exe`. Це автономна збірка, окремий .NET Runtime не потрібний. Файли PDB у вихідній папці потрібні лише для діагностики.

Фінальна автоматична перевірка: **238 тестів пройдено в Release, 0 помилок, 0 пропущено**. Покрито старий конвеєр і JSON-профілі, ESL, резервні копії, захист гри, мечі, COBJ, LVLI, імпорт ресурсів, відкат помилок, переходи майстра, перевірку полів, підсумок і фінальний запис. Інтеграційні тести перевіряють точний склад ZIP із NIF/DDS у чотирьох режимах ESL/копіювання, незмінність джерел, відсутні файли після перегляду, пакування безпосередньо з майстра й збереження прив’язки при редагуванні/дублюванні профілю. П’ять кроків WPF перевіряються при ширині 420, 600, 900 і 1200, а також при масштабі 130%; окремий тест перевіряє перебудову колонок і висоти рядків. Тестові файли синтетичні; власна копія гри для тестів не потрібна.

Погоджене розширення сценарію імпорту власної NIF-моделі й покрокового інтерфейсу описане в [ТЗ](docs/weapon-workflow-spec.md). Реалізацію етапів 1–5 завершено; ручна перевірка в грі й xEdit залишається окремою приймальною перевіркою.

Для знімків WPF можна додати до команди тестів `--environment SKYRIM_UI_PREVIEW_DIR=C:\Temp\SkyrimUiPreview` (абсолютний шлях до бажаної папки).

### VS Code: CS0103 для згенерованих властивостей

Властивості на кшталт `ResourceStatus` створює CommunityToolkit.Mvvm із поля `[ObservableProperty] _resourceStatus`. Відкривайте корінь репозиторію з `SkyrimModPacker.sln`, а не окремий `.cs` як самостійну програму. У `.vscode/settings.json` зафіксовано solution, увімкнено автоматичне виконання генераторів і вимкнено окремі file-based programs для цього workspace.

Якщо після оновлення робочої області лишилися старі повідомлення, виконайте **Ctrl+Shift+P → Developer: Reload Window** і дочекайтеся завантаження solution. Вибраний контекст файлу має бути `SkyrimModPacker.UI`. Перевірка реальної компіляції: `dotnet build SkyrimModPacker.sln -c Debug`. Не додавайте вручну дублікати властивостей, які вже генерує Toolkit.

### Ручна приймальна перевірка

- Старий профіль із вимкненим ESL: **Сканувати → Запакувати**, перевірити ZIP у вихідній папці й його вміст.
- Сумісний плагін: увімкнути ESL у профілі, запакувати, перевірити наявність `.bak`; відкрити плагін з архіву в xEdit і перевірити прапорець **ESL / Small master**, незмінність FormID. Несумісний плагін має зупинити збірку з поясненням у журналі.
- Створити меч із ванільного шаблону, додати рецепт або список за потреби, прив’язати профіль і запакувати. Встановити ZIP через менеджер модів у тестовий профіль, увімкнути плагін та перевірити меч у грі (пошук через консоль `help`, потім `player.additem` з ID запису у фактичному порядку завантаження).

Перевірка в реальній грі й xEdit ще не виконана: автоматичні тести використовують синтетичні дані, а WPF-перевірки — тестовий рендеринг. Вони не підтверджують вигляд моделі або поведінку в конкретній збірці модів.
