# BC7, інгредієнти, спільна модель та leveled lists — 24.10.2026

## 1. BC7 як ресурс SE/AE

Додано `DdsResourceInspector`, незалежний від декодера 3D-перегляду. DDS із DX10-заголовком та DXGI 98/99 розпізнаються як BC7. Перевіряються magic/розмір заголовка, розміри зображення, кількість і повнота mip-рівнів, тип поверхні, обсяг даних і коректність префікса режиму блоків BC7. Для кубічних текстур враховуються шість граней. Масиви, об’ємні та невідомі формати відхиляються з назвою файлу й причиною. Сканування BC7 підтримує скасування.

Перевірка застосована до імпорту окремих файлів, batch/папок, копії у staging перед публікацією, заміни/відновлення ресурсу, каталогу, перевірки ресурсів і підготовки ZIP. Каталог показує формат, розміри й mip-рівні. Різні байти за тим самим шляхом не перезаписуються мовчки. Коректні BC7 імпортуються та пакуються без конвертації й зміни байтів.

Тести охоплюють BC7 UNORM/sRGB, обрізаний payload, некоректний заголовок, невідомий DXGI, пошкоджений режим BC7 і відсутні mip-рівні. Окремо імпортовано й запаковано всі чотири наявні DDS користувацького Fang of Namira: BC7 BaseColor/Normal/Emissive та DXT5 bronze_e. SHA-256 джерел і файлів у ZIP збігаються.

3D-декодер зберігає попередні межі BC1/BC2/BC3. Для BC7 повідомлення прямо каже, що імпорт/ZIP підтримуються, а перегляд текстури недоступний. Модель показується з нейтральним матеріалом. Це не помилка ресурсної перевірки.

Первинні джерела формату: [Microsoft DDS_HEADER_DXT10](https://learn.microsoft.com/en-us/windows/desktop/direct3ddds/dds-header-dxt10), [Microsoft DirectXTex DDS loader](https://github.com/microsoft/DirectXTex/blob/main/DirectXTex/DirectXTexDDS.cpp).

## 2. Інгредієнти

У крафті й покращенні є «Додати інгредієнт», пошук за назвою/EditorID, підписане редаговане поле «Кількість» та видалення рядка. Повторний вибір предмета збільшує його наявну кількість на 1. Новий прихований дубль не додається. Якщо кількість некоректна або досягла межі Int32, рядок не змінюється та показується помилка.

Допустимі цілі значення 1–2147483647 — тип Count у CNTO/COBJ. Нуль, від’ємні, дробові й переповнення блокують запис та мають пояснення біля поля. Невалідний текст зберігається лише як чернетка.

Приймальні тести для обох видів рецептів: 9 злитків + повторний вибір = 10, додавання смужок шкіри, запис плагіна, перевірка справжніх COBJ і повторне відкриття майстра. Кількості та посилання збігаються.

## 3. Один NIF для двох видів

Перемикач «Використовувати цю модель також для першої особи» копіює призначення третьої особи в першу. Поки він увімкнений, зміна основного шляху синхронізує обидва види. Окремий вибір іншого NIF першої особи вимикає цей режим. Після вимкнення можна редагувати шляхи незалежно.

У чернетку додано необов’язкове поле `UseSharedModel`, початково false. Старі документи читаються без міграції; при формуванні полів із записів плагіна однакові непорожні шляхи визначають спільний режим. Дублювання предмета та збереження чернетки зберігають перемикач. Відновлення моделей зразка скидає явний спільний режим.

Сервіс записує WNAM через належний STAT, а обидва записи посилаються на один зареєстрований файл. Приймальний тест пакує всю чергу зі спільним NIF, перевіряє WEAP/STAT першої/третьої особи, одну NIF у ZIP та повторне відкриття. Тести не трактують однакові шляхи як помилку.

**Відображення у самій Skyrim від першої й третьої особи ще не перевірене.** Збіг шляхів не доводить правильність хвату, анімації, камери та сумісності NIF. Мод автоматично не встановлювався. Живий огляд ПК у попередній спробі був недоступний через `CreateProcessWithLogonW failed: 2`; цю перевірку не підмінено автоматизованими тестами.

## 4. Leveled lists

Загальна побудова майстра збережена. Додано окремий необов’язковий блок із поясненням випадкової здобичі, пошуком, фільтрами, назвою фактичного використання, EditorID, джерелом, складом списку й підсумком перед записом. Поля підписані «Мінімальний рівень для цього запису» та «Кількість предметів». Обидва приймають 1–32767. Є дія «Пропустити додавання до випадкової здобичі».

Категорії встановлюються лише за прямими посиланнями записів:

- контейнери — список у вмісті CONT;
- торговці — FACT.MerchantContainer → REFR.Base → CONT → список;
- спорядження — список в інвентарі NPC або OTFT;
- без підтверджених прямих посилань — «Призначення не визначено».

Не робиться висновок про призначення лише зі слів Vendor/Loot/Equipment у EditorID. Це перевірено спеціальним тестом. Вкладені списки показані в складі; їхня непряма роль не вгадується. Один список може мати кілька підтверджених призначень. Для відомих прапорців додано зрозумілі правила вибору; для SpecialLoot/невідомих прапорців точний результат позначено невизначеним. Фактична поява залежить від гри, рівня, chance none, вкладених списків і модів.

На встановлених Skyrim.esm/Dawnguard.esm лише для читання перевірено **3181** список: **327** мають використання у звичайних контейнерах, **173** — у торговців, **440** — у спорядженні; **2386** не мають підтвердженої прямої категорії. Категорії можуть перетинатися. Звіт: `artifacts/audit/real-leveled-list-catalog.json`. SHA-256 Skyrim.esm до/після збігається.

Майстер додає LVLI з `UpdateExisting = true`. Повторення тих самих параметрів не змінює байтів плагіна. Інший рівень/кількість оновлюють один наявний запис із збереженням інших полів та порядку за рівнем. Кілька старих збігів не зливаються мовчки. Старі виклики ручного редактора з початковим false зберігають попереднє правило явного видалення дубля.

Джерела структури: [Mutagen Faction](https://github.com/Mutagen-Modding/Mutagen/blob/dev/Mutagen.Bethesda.Skyrim/Records/Major%20Records/Faction.xml), [Mutagen LeveledItem flags](https://github.com/Mutagen-Modding/Mutagen/blob/dev/Mutagen.Bethesda.Skyrim/Records/Major%20Records/LeveledItem.cs).
