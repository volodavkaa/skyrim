# Етап 1, завдання 5: атомарне JSON-збереження

Статус: виконано. Наступне завдання — узгоджене блокування запису плагінів, повторне читання й перевірка перед заміною. До нього не переходили.

## Виконано

- Спільний внутрішній `AtomicJsonFile<T>` використовується репозиторіями `settings.json`, `profiles.json` і `build_history.json`. Контракти, моделі, camelCase та форматування JSON збережені, нових NuGet-пакетів немає.
- Семофор за нормалізованим шляхом та ексклюзивний файловий дескриптор `.lock` охоплюють повний цикл читання–зміни–запису. Різні екземпляри репозиторію не втрачають паралельні зміни різних профілів або додавання історії. Операції різних JSON-файлів незалежні.
- Перше читання налаштувань і створення типових значень виконуються під тим самим блокуванням: початкове завантаження не перезаписує вже збережені користувацькі налаштування.
- Новий документ серіалізується в унікальний сусідній `.<ім’я>.<guid>.tmp`, виконується `FlushAsync` та `Flush(flushToDisk: true)`. Після завершення запису `File.Replace` замінює наявний JSON, залишаючи його попередню версію у `.bak`. Для першого створення використовується `File.Move` без перезапису.
- Скасування перевіряється перед заміною. Помилка серіалізації, скасування або відхилена заміна зберігають попередній JSON. Скасування після вже виконаної заміни не змінює успішний результат збереження.
- Власний тимчасовий файл видаляється при звичайному виході через помилку чи скасування. Якщо очищення також не вдалося, початковий виняток зберігається, а додаткова помилка й шлях потрапляють у його `Data` та доступний логер.
- Пошкоджений JSON повідомляє помилку із шляхом до файлу. Збереження й очищення не приховують її та не перезаписують пошкоджений файл або справну резервну копію. JSON `null` зберігає попередню поведінку повернення типових значень.
- Перевірки шляхів відхиляють junction і символічні посилання для файлів даних, резервних та службових файлів. Помилки доступу до `.lock` не перетворюються на нескінченне повторення; повторюються лише конфлікти відкритого дескриптора з підтримкою скасування.
- DI передає репозиторіям наявні логери, зберігаючи їхні інтерфейси та singleton-час життя.


Перевірено точний попередній вміст `.bak`, невдалу заміну відкритого файлу, скасування перед записом і під час серіалізації, виняток серіалізації, пошкоджені документи, паралельні створення/оновлення/видалення профілів, додавання та очищення історії, цілісність паралельних знімків налаштувань, одночасне початкове завантаження й збереження, звільнення блокування після помилок, некоректні шляхи резервної копії та блокування. Раніше зафіксований нестабільний тест збереження ESL-опції профілю пройшов у цільовому й повному наборах. Його початкова причина не встановлена; ці запуски не доводять, що нестабільність усунуто.

## Ручна перевірка та обмеження

- Тести використовують власні тимчасові каталоги та синтетичні дані. Особисті налаштування, встановлена гра та її Data не змінювалися. Skyrim і xEdit не запускалися; ручна перевірка через UI не виконувалася.
- `.lock` навмисно залишається порожнім файлом після операції. Блокування визначається відкритим дескриптором, а не існуванням цього файлу; завершення процесу звільняє дескриптор. Не видаляйте файл під час роботи програми.
- Блокування узгоджує роботу екземплярів програми з цим механізмом. Сторонні редактори можуть його ігнорувати. Для одного профілю або повного набору налаштувань останнє завершене збереження замінює попередній знімок; злиття змін окремих полів не реалізовано.
- Атомарність стосується одного файлу. Спільної транзакції між трьома файлами, JSON проєкту, ресурсами, плагіном та ZIP тут немає. Запис `mod-project.json` і плагінів належить наступному завданню.
- Перевірено локальну файлову систему Windows. Примусове завершення, втрата живлення, мережеві файлові системи та відмови обладнання окремо не моделювалися. Примусове завершення може залишити `.tmp`; автоматичного пошуку таких файлів немає.
- Автоматичного відновлення пошкодженого JSON немає. Для ручного відновлення закрийте програму, збережіть копію пошкодженого файлу та відновіть основний файл із перевіреної `.bak`. Резервна копія містить одну попередню версію, а не всю історію.
