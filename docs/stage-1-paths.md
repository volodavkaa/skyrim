# Етап 1, завдання 3: захист шляхів

Статус: виконано. Наступне завдання — загальне очищення staging та явний стан завершення конвеєра; до нього не переходили.

## Зміни

- Спільний `PackingPathGuard` перевіряє відносні шляхи, абсолютні адреси, відповідність джерела дозволеному кореню та колізії ZIP.
- Заборонені traversal, кореневі ZIP-шляхи, префікси пристроїв, потоки NTFS, порожні компоненти, зарезервовані імена Windows, кінцеві пробіли та крапки.
- Джерела мають відповідати Data або каталогу проєкту; явно налаштований зовнішній плагін залишається дозволеним джерелом.
- Запис у гру блокується для всіх профілів. Сам Data та шляхи джерел/результатів перевіряються на junction і символічні посилання, включно з посиланнями на видалений каталог.
- Сканер не обходить каталоги через посилання. ZIP перевіряє список файлів до видалення наявного архіву та не дозволяє вихідному ZIP збігатися з джерелом.
- Кроки копіювання, ESL та архівації використовують спільну перевірку staging. Сторонній каталог не архівується й не видаляється як staging. Відсутній staging не підміняється початковими джерелами.
- Очищення staging видаляє вкладене посилання без переходу до його цілі.


Фінальна збірка: 0 помилок, 0 попереджень. Фінальний набір: 373 успішних, 0 невдалих, 0 пропущених. Звіт: `artifacts/audit/packing-paths-release-final.trx`.

Проміжні результати не приховуються:

- Перший запуск частини старих тестів: 63 успішних, 4 невдалих через відсутній Data та невідповідні джерела у фікстурах. Фікстури виправлено.
- Аналізатор видав `xUnit2009` для перевірки префікса; assertion виправлено, фінальна збірка без попереджень.
- Після уніфікації staging один тест перевіряв попередній текст помилки для папки гри. Порядок перевірок виправлено зі збереженням потрібної діагностики.
- Тест із junction усередині staging відтворив помилку доступу при рекурсивному очищенні. Очищення замінено на обхід без переходу за посиланнями; тест тепер проходить і підтверджує незмінність цільового каталогу та попереднього ZIP.
- Наявний `EslPackingTests.Profile_EslOption_RoundTripsThroughEditingAndDuplication` один раз упав на початковому `EnableEsl`. У наступних цільових і двох повних запусках пройшов; причина окремо не встановлена. Його початкове завантаження слід перевірити в завданні синхронізації. Код цього тесту та `ProfilesViewModel` не змінювався.

## Ручні перевірки й обмеження

- Junction створювалися та перевірялися автоматичними тестами лише у власних тимчасових каталогах. Гра та xEdit не запускалися; файли встановленої гри не змінювалися.
- Нових NuGet-пакетів, зміни архітектури чи формату JSON немає.
- Програма тепер вимагає безпосередніх абсолютних шляхів без `.`/`..` і не приймає junction/symlink як налаштований Data або частину шляху пакування.
- Захист від одночасної зовнішньої підміни файлової системи між перевіркою та операцією окремо не підтверджувався.
- Заміна готового ZIP після попередніх перевірок усе ще не атомарна; повторна перевірка ZIP і SHA-256 залишаються наступними завданнями.
