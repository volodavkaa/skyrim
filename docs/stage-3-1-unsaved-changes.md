# Завдання 3.1 — незбережені зміни

Реалізовано індикатор незбережених змін зброї/рецепта і вибір «Зберегти зміни / Відкинути зміни / Продовжити редагування» перед діями, які можуть замінити редактор або закрити застосунок. Завдання 3.2 та наступні не розпочато.

## Межі стану

| Дані / операція | Поведінка |
|---|---|
| EditorID, назва, шкода, вага, вартість, опис, швидкість, досяг | Незбережений стан зброї |
| Шляхи моделей першої/третьої особи, явне відновлення ванільної моделі | Незбережений стан зброї; відстежуються також наміри зміни WNAM/метаданих |
| Keyword, звук, зачарування, заряд | Незбережений стан зброї, включно з додаванням/видаленням і заміною колекції Keyword |
| EditorID рецепта, кількість результату, верстат, perk, склад і кількості інгредієнтів | Незбережений стан рецепта |
| Явна команда «Новий меч» / «Новий рецепт» | Новий незбережений предмет/рецепт, навіть до подальшого редагування |
| Автоматично підставлений шаблон без ручних змін | Початковий стан; сам собою не спричиняє попередження |
| Імпорт NIF | Файл і реєстрація записуються одразу; призначення моделі зброї залишається незбереженим до запису зброї |
| Імпорт DDS | Файли й реєстрація записуються одразу; сам імпорт не позначається незбереженою чернеткою |
| Видалення записів, застосування змін LVLI, створення/прив'язування профілю | Як і раніше, записуються одразу; не відкочуються вибором «Відкинути зміни» |
| Пошук, перегляд каталогу, крок майстра, вибір кандидата Keyword/інгредієнта, кількість ще не доданого інгредієнта, параметри майбутньої операції LVLI, параметри створення проєкту | Параметри інтерфейсу; не є змінами запису до відповідної команди |

Порівнюються сирі рядки полів, тому неправильне числове значення теж захищене від втрати. Повернення звичайного поля до початкового значення прибирає його внесок в індикатор. Різне текстове представлення того самого числа, наприклад `1` та `1.0`, може залишати індикатор до збереження. Явний новий запис і намір відновлення моделі враховуються окремо.

Збереження зброї не скидає незбережені поля рецепта. Загальна команда збереження спочатку створює/оновлює зброю, якщо потрібно, а потім записує рецепт. Якщо друга операція не вдалася, вже записана зброя залишається збереженою, рецепт — незбереженим, а перехід або закриття блокується. Спільної транзакції зброї та рецепта не додано.

## Захищені переходи

- Закриття головного вікна, у тому числі коли відкрито іншу сторінку програми.
- Відкриття проєкту чи окремого плагіна, створення нового проєкту, імпорт робочої копії.
- Вибір іншого предмета або шаблону, явний новий меч, видалення предмета.
- Вибір іншого рецепта, новий рецепт, завантаження списку рецептів і видалення рецепта. Ці переходи перевіряють рецепт окремо й не скидають поля зброї.
- Явне перезавантаження шаблонів або вибір Data.

Вибір «Продовжити редагування», Escape та закриття діалогу залишають редактор відкритим. Вибір «Зберегти» дозволяє перехід тільки після успішного запису відповідних даних. Помилка валідації/запису, скасування чи збій самого prompt не дають дозволу на перехід. Під час активної операції або іншого запиту переходу другий запит блокується.

«Відкинути» дозволяє замінити редактор без запису його полів. До фактичного успішного переходу поточні дані залишаються в пам'яті: проста помилка відкриття цільового файла не повинна завчасно споживати чернетку. Це не команда відновлення файлів і не відкат уже виконаного імпорту.

UI-списки використовують окремі властивості запиту вибору; підтверджений предмет/рецепт змінюється після перевірки. Тимчасовий `null` від WPF при оновленні або фільтрації списку не очищає редактор і не запускає повторні діалоги. Внутрішні властивості `SelectedWeapon/SelectedTemplate/SelectedRecipe` залишені для програмного заповнення; користувацькі bindings спрямовані через захищені властивості вибору.

Редактор зареєстровано як singleton у чинному DI: навігація на інші сторінки й повернення не створює іншу чернетку. Закриття головного вікна перевіряє той самий екземпляр. Повторна ініціалізація не підміняє Data з налаштувань, якщо є незбережені дані; користувач має спочатку зберегти їх або явно вибрати Data з відповідним рішенням.

На сторінці є локалізований індикатор і кнопка загального збереження. Пакування зі сторінки зброї блокується також за наявності незбереженого рецепта; чернетка не може непомітно залишитися поза ZIP. Старий конвеєр профілів продовжує пакувати збережені файли.

## Збереження попередньої роботи та обмеження

Початкова база — `950f62e` із незакоміченими результатами 2.3/2.4. Перед змінами створено `artifacts/backups/stage-3-1-20261023-211607`, включно з новими файлами попередніх етапів. `WeaponModelTests.cs`, `WeaponProjectTests.ModelPackingValidation.cs` і звіти 2.3/2.4 не редагувалися; попередній README збережено з доповненням 3.1. Комітів не створено.

- Незбережений стан існує тільки в пам'яті. Автозбереження, файли чернеток, відновлення після збою, Undo/Redo і відкат імпортованих ресурсів у 3.1 не реалізовані.
- Примусове завершення процесу, збій ОС або втрата живлення можуть втратити незаписані поля. Звичайне Closing не гарантує захист від примусового shutdown.
- Save all не є атомарною транзакцією кількох записів. У разі часткового успіху звіт про помилку й стан рецепта зберігаються, але вже записану зброю автоматично не відкочують.
- Захист від довільних зовнішніх змін і зміна політики конфліктів запису не входили до 3.1; чинні файлові перевірки builder залишені.
- Модель/рецепт, які потребують вибору шаблону, робочого плагіна або виправлення полів, не можна зберегти лише натисканням Save у prompt. Перехід блокується, щоб користувач міг виправити причину або явно відкинути поля.
- Програмне пряме присвоєння внутрішнього committed selection призначене для завантаження; майбутні користувацькі переходи теж мають використовувати захищений маршрут.

Наступне завдання — **3.2, чернетки та автозбереження**. Його не розпочато. Після цього звіту — очікування команди «далі».
